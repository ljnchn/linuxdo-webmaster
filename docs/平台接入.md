# Linux.do 平台接入与可信存档

## 当前交付状态

- 浏览器试玩使用本机存档，不是全球排行榜。
- `server/` 为可运行的 Node 24 + SQLite 后端，已用本地自动化测试验证业务事务与 HTTP 边界。
- `mapp/` 使用官方 `getSDK()`，没有 window 假 SDK，也不把当前用户资料当服务端鉴权。
- 没有平台分配的应用 ID、批准的 HTTPS 端点、官方 SDK 本地目录及 sandbox 环境，因此**未生成可上传包、未上线、未通过 Linux.do sandbox 真机验收**。
- 未下载秘密、申请线上凭据、创建账户或公开部署。JWT 验证只需社区公开 JWKS，绝不索要私钥。

## 1. 本机后端开发

在项目根目录运行：

```sh
DEV_MODE=enabled HOST=127.0.0.1 PORT=8787 node server/index.mjs
node --test tests/server.test.mjs
```

默认不开放开发身份。只有 `DEV_MODE=enabled` 且绑定 loopback 才允许一个固定 local-tester；正文与 header 自报 user_id 均不能改变身份。开发前端 origin 默认 `http://127.0.0.1:4173`，可用 `DEV_ORIGIN` 显式配置。请不要把开发服务通过公网反代公开。生产启动不设置 DEV_MODE。

数据写入 `data/development.sqlite`；sandbox 与 production 分别写入对应文件。`DATA_DIR` 可指定持久卷目录。每个库另存 channel 元数据，即使误用同一文件也拒绝跨环境打开。SQLite 文件与 WAL 需要一同正确备份；正式部署需备份/恢复演练、磁盘监控与访问权限设置。

## 2. API 合约

所有业务接口需认证；`/health` 仅返回服务状态与环境。

| 接口 | 请求 | 响应 |
| --- | --- | --- |
| GET /api/state | 无正文 | `{state, revision}`，首次创建服务端种子存档 |
| POST /api/actions | `{revision,idempotencyKey,action}` | `{state,revision}` |
| GET /api/leaderboard?sort=members | `sort=members` 或 `days` | `{channel,entries:[{rank,name,members,days}]}`，最多 100 条 |
| GET /health | 无 | `{ok:true,channel}` |

`idempotencyKey` 为 16–96 位字母数字/下划线/连字符，可用 UUID。超时后必须保留同一完整操作及 key 重试；不要立即改 key。相同 key+操作返回原响应，key 被不同操作重用返回 409；旧 revision 返回 409，客户端重新读取存档后让玩家决定下一步。不同操作不能复用 key。服务端不会接收整个存档、余额、成绩或 user_id。

支持动作：

```json
{"type":"rent","serverId":"nest","days":7}
{"type":"renew","days":7}
{"type":"advance","periods":1}
{"type":"advance","days":1}
{"type":"advance","days":7}
{"type":"claim","id":"all"}
{"type":"resolve","eventId":"事件实例ID","optionId":"选择ID"}
{"type":"strategy","strategy":"balanced"}
{"type":"rename","name":"我的小站"}
{"type":"restart"}
```

多余字段拒绝；完整正文最多 8 KiB；必须 application/json。规则验证失败为 422，认证失败 401，CORS 来源错误 403，非法参数 400；错误体为 `{error,message}`。restart 仅本局结束后允许，重开时 revision 单调递增。旧v1存档及历史幂等响应自动迁移为v2，不重扣租费。没有任意 delete API。

身份主键是验签后的 `[iss,sub]`；榜单只查询已经租用服务器开站的服务端记录，未开站的新号不入榜；不暴露认证主键。日数仅主动推进改变。每次成功动作的存档、幂等响应、审计记录在同一 `BEGIN IMMEDIATE` 事务提交；错误回滚。重复操作不重复审计或扣款。排行榜排序为主指标、次指标、服务端随机固定公开 ID，姓名是玩家自选的小站名而非已认证用户名。

## 3. 平台后端配置

官方源码：https://github.com/linux-do/mapp-developer-guide

从该仓库取得官方 `sdk/` 后，在部署项目中安装该本地包，使 Node 可以解析 `@discourse-mini-app/sdk/server`。例如在审核并确定 SDK 路径后执行 `npm install /absolute/path/to/mapp-developer-guide/sdk`。当前项目没有自动安装或冒充这个依赖。

正式/沙盒各自设置：

```sh
PLATFORM_ISSUER=https://实际社区地址
PUBLIC_ORIGIN=https://实际后端域名
MINI_APP_ID=平台实际分配的UUIDv7
PLATFORM_CHANNEL=sandbox
HOST=127.0.0.1
PORT=8787
DATA_DIR=/实际持久卷路径
```

issuer 包含论坛子路径（如有）且无末尾斜线。PUBLIC_ORIGIN 为后端固定 HTTPS origin，不接受请求 Host/转发头覆盖。TLS 终止反向代理不得改写原始路径与 query 字节；若必须改写，先明确部署映射并修改受信任的配置逻辑。

启动从固定 `${issuer}/mini-app-api/jwks` 读取公开 EC P-256 ES256 JWK，禁止重定向并验证形状；缺配置、缺 SDK、JWKS 不可用都终止启动。每 5 分钟刷新并缓存；刷新失败只保留已信任公钥，绝不跳过验签。首版只保存当前单公钥，轮换时旧令牌可能短暂 401，新调用重新取得授权；没有按未验证 kid/iss 下载任意地址。正式发布前按社区轮换流程决定是否添加受控旧公钥保留。

每次请求调用官方 `verifyPlatformRequest` 核验 issuer、audience、appId、channel、scope、method、完整固定外部 URL 与 JWT。Cookie 不作回退。标准 CORS 预检不需 JWT，普通业务 OPTIONS 不跳过认证。错误响应同样给匹配论坛 origin 的 CORS。

## 4. 客户端适配器

```js
import { initializeMapp } from './mapp/adapter.mjs';
await initializeMapp({ render: transport => mountGame(transport) });
```

初始化顺序：`getSDK()` → `await sdk.ready` → 检查权限 → `sdk.user.getCurrent()` → 渲染 → `sdk.lifecycle.ready()`。失败时显示错误且通知生命周期完成，绝不静默降级成本机成绩。transport 暴露 `mode: 'platform'`、展示用 user、getState()、sendAction({revision,idempotencyKey,action})、getLeaderboard(sort)。所有网络都使用 `sdk.http.request` 与已声明端点，不走 fetch，不持有/拼造 JWT。

## 5. 构建真实平台包

使用 Bun 1.4.3+、Vite 8.3.5、官方 SDK 0.3.0（本次读取版本）。Vite 需在此项目可解析，例如 `bun add --dev vite@8.3.5`；不要把示例 app ID 当自己的 ID。

```sh
MINI_APP_ID=平台实际分配ID \
PUBLIC_ORIGIN=https://实际后端域名 \
MAPP_SDK_PATH=/绝对路径/mapp-developer-guide/sdk \
MINI_APP_VERSION=0.3.0 \
bun mapp/build.mjs
```

脚本阻止缺失/占位/文档示例 ID 与 example 域名，检查官方 SDK 包名与 Bun 版本，实际导入官方 pack。UUID 形状校验不能证明所有权，开发者必须确认 ID 确由平台分配给本应用。输出单 IIFE app.js、单 app.css、正文 index.html、strings.json，经官方 pack 生成 `dist/mapp-package/app.zip`。`manifest.template.json` 只申请 user.read/network.request；三个端点均 auth:platform，只有 leaderboard 声明 sort 动态 query。当前未用主题读取，不额外申请权限。

## 6. 上线前必须完成

1. 确认应用 ID、社区 issuer、公钥来源、后端 origin 与端点审核授权。
2. 部署 HTTPS 后端与持久存储，不公开开发模式；加反向代理请求限流和磁盘/错误监控。
3. sandbox 分库实测登录、过期/错误 JWT、URL/method/scope/channel 不匹配、401 恢复、CORS、网络中断同 key 重试及多标签页 revision 冲突。
4. 确认连续点击不会多扣钱，跨设备服务端存档一致，模拟身份/客户端改成绩无效。
5. 按平台流程提审、手动发布。此项目没有执行这些线上操作。

本地测试不等于平台验签集成通过。首版未实现多实例限流、账号封禁、审计归档或自动备份；JWT 也不能证明玩家是真人。幂等操作表和审计表需要后续保留策略，不能随意清理仍可能重试的操作记录。

参考：官方 docs/server-auth.md、docs/sdk-network.md、sdk/README.md、sdk/server.d.ts、demos/README.md、demos/game-2048/vite.config.ts（2026-11-10 读取）。
